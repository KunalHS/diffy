# Diffy Commands

This document captures the first draft of the Diffy command model. Names are not final. The goal is to make the common comparison flows easy to run from the terminal and easy to discover from the TUI.

## Default Entry

Status: Approved

```bash
diffy
```

Opens the local changes view. This is the most basic workflow, so bare `diffy` should not show a generic home screen.

Default behavior:

- show local changes
- separate unstaged and staged changes
- include untracked files in the file list
- open directly into the TUI diff/file view

Underlying Git commands:

```bash
git diff
git diff --staged
git status --short
```

Possible future chooser command:

```bash
diffy choose
```

## Help

Status: Approved

```bash
diffy --help
diffy local --help
diffy compare --help
diffy review --help
diffy recent --help
diffy stash --help
diffy history --help
diffy commit --help
```

Expected behavior:

- `diffy --help` lists all approved commands, aliases, and shared options.
- Command-specific help explains only that command family.
- `diffy compare --help` and `diffy review --help` should show the same help and mention that `compare` and `review` are aliases.
- Help output should clearly separate approved commands from future/parked ideas.

## Alias Rules

Status: Approved

Aliases should make commands faster, but they should not be stackable.

Invalid examples:

```bash
diffy compare review live
diffy review compare live
diffy local diffy
```

Equivalent option aliases should also not be passed together.

Invalid examples:

```bash
diffy compare live --file src/App.ts --path src/App.ts
diffy local --file src/App.ts --path src/App.ts
diffy compare live --raw --no-tui
```

Expected behavior:

- Show a clear error explaining that the aliases are equivalent.
- Suggest one valid command form.

## Local Changes

Status: Approved

```bash
diffy local
```

Opens the local changes view. This is the explicit named form of bare `diffy`.

Bare default:

```bash
diffy
```

Named form:

```bash
diffy local
```

Both should open the same local changes workflow.

The view should have tabs or toggles for unstaged and staged changes.

Direct flags:

```bash
diffy local --unstaged
diffy local --staged
diffy local --file
diffy local --file path/to/file.ts
diffy local --path
diffy local --path path/to/file.ts
diffy --file
diffy --file path/to/file.ts
diffy --path
diffy --path path/to/file.ts
```

Underlying Git commands:

```bash
git diff
git diff --staged
git status --short
```

Notes:

- `--unstaged` shows working tree changes not staged.
- `--staged` shows what will go into the next commit.
- Untracked files should appear in the file list. Their full patch needs to be generated by Diffy because plain `git diff` does not include untracked files.
- `--file <path>` restricts the local changes view to that file.
- `--file` without a path opens an interactive file selector from locally changed files.
- `--path` is an alias for `--file` and works the same way.
- The local changes TUI should have a shortcut to restrict to a file.
- When file restriction is active, the shortcut bar should show an action to remove the file restriction.

## Compare Branches

Status: Approved

```bash
diffy compare
diffy review
diffy <target-branch>
diffy compare <target-branch>
diffy review <target-branch>
diffy <source-branch> <target-branch>
diffy compare <source-branch> <target-branch>
diffy review <source-branch> <target-branch>
```

Shows branch changes as they would appear in a review or merge direction.

The words `compare` and `review` are aliases. Positional branch arguments on bare `diffy` are also aliases for the same workflow.

Parsing rule:

- `diffy` with no args opens local changes.
- `diffy <target-branch>` means `diffy compare <target-branch>`.
- `diffy <source-branch> <target-branch>` means `diffy compare <source-branch> <target-branch>`.
- Known subcommands win over branch shorthand. For example, `diffy local` opens local changes, not a branch named `local`.

### Current Branch Against Target

Examples:

```bash
diffy live
diffy compare live
diffy review live
diffy main
diffy compare main
diffy compare origin/main
```

Meaning:

```text
show changes from the current branch as if it were being merged into the target branch
```

Underlying Git command:

```bash
git diff <resolved-target>...HEAD
```

Resolution rules:

1. If the argument explicitly starts with `origin/`, use that exact remote ref.
2. Otherwise, if `<target-branch>` exists locally, use it.
3. If not, try `origin/<target-branch>`.
4. If neither exists, show a clear error.

Interactive form:

```bash
diffy compare
```

Expected behavior:

- Show an interactive branch picker.
- The selected branch becomes the target branch.
- Always show the resolved comparison before rendering the diff.
- The picker can use something like `git branch | fzf --reverse` in a simple implementation.

Example display:

```text
Comparing: current branch -> origin/live
Git: git diff origin/live...HEAD
Files: 8   +142 -37
```

The compare TUI should have a shortcut to toggle back to local changes only when the source side of the comparison is the current branch or `HEAD`. Users often need to check local edits while reviewing their current branch, but local changes are unrelated when comparing two other branches.

Examples where the local changes shortcut should appear:

```bash
diffy compare live
diffy review live
diffy live
diffy compare HEAD live
```

Examples where the local changes shortcut should not appear unless the source resolves to the current branch:

```bash
diffy compare b1 b2
diffy review b1 b2
diffy b1 b2
```

The compare TUI should also have a shortcut to restrict the current comparison to a file. Pressing it opens a file selector populated from the changed files in the active comparison. When file restriction is active, the shortcut bar should show an action to remove the file restriction.

The compare TUI should have a toggleable commits screen or panel. This should show the commits included in the comparison without replacing the diff workflow.

### Source Branch Against Target Branch

```bash
diffy <source-branch> <target-branch>
diffy compare <source-branch> <target-branch>
diffy review <source-branch> <target-branch>
```

Examples:

```bash
diffy feature/login live
diffy compare feature/login live
diffy review feature/login live
diffy bugfix/a main
diffy compare bugfix/a main
diffy compare release/25.1 release/25.2
```

Meaning:

```text
show changes from source branch as if source were being merged into target branch
```

Underlying Git command:

```bash
git diff <resolved-target>...<resolved-source>
```

Resolution rules:

1. If an argument explicitly starts with `origin/`, use that exact remote ref.
2. Otherwise resolve that branch name locally first.
3. If a branch is not found locally, try `origin/<branch>`.
4. If either branch still cannot be resolved, show a clear error naming the missing branch.

## Compare With File Or Path Restriction

Status: Approved

All `diffy compare` and `diffy review` forms should support restricting the comparison to one file or path. `--path` is an alias for `--file`.

With a path value:

```bash
diffy live --file "path/to/file with spaces.ts"
diffy live --path "path/to/file with spaces.ts"
diffy compare live --file "path/to/file with spaces.ts"
diffy compare live --path "path/to/file with spaces.ts"
diffy review live --file "path/to/file with spaces.ts"
diffy live --file path/to/file.ts
diffy live --path path/to/file.ts
diffy compare live --file path/to/file.ts
diffy b1 b2 --file path/to/file.ts
diffy b1 b2 --path path/to/file.ts
diffy compare b1 b2 --file path/to/file.ts
```

Underlying Git commands:

```bash
git diff <resolved-target>...HEAD -- <path>
git diff <resolved-target>...<resolved-source> -- <path>
```

Without a value, `--file` or `--path` opens an interactive file selector.

```bash
diffy live --file
diffy live --path
diffy compare live --file
diffy review live --file
diffy b1 b2 --file
diffy b1 b2 --path
diffy compare b1 b2 --file
diffy review b1 b2 --file
diffy compare --file
diffy compare --path
diffy review --file
```

Expected behavior:

- `diffy compare live --file` compares current branch to `live`, then opens a file selector from changed files.
- `diffy compare b1 b2 --file` compares `b1` to `b2`, then opens a file selector from changed files.
- `diffy compare --file` first opens the branch selector, then opens the file selector.
- The file selector should only show files changed in the active comparison.
- The resulting view should clearly show that it is restricted to a file.
- The TUI should provide a shortcut to remove the file restriction and return to the full comparison.

## Ahead Of Upstream

Status: Approved

```bash
diffy ahead
```

Shows local branch changes that are not on the upstream remote yet.

Underlying Git commands:

```bash
git diff @{u}...HEAD
git log --oneline @{u}..HEAD
```

Expected behavior:

- If the current branch has no upstream, show a clear error.
- Show both changed files and local-only commits.
- This is a convenience shortcut for comparing the current branch against its configured upstream.

## Behind Upstream

Status: Approved

```bash
diffy behind
```

Shows upstream changes that are not in the local branch yet.

Underlying Git commands:

```bash
git diff HEAD..@{u}
git log --oneline HEAD..@{u}
```

Expected behavior:

- If the current branch has no upstream, show a clear error.
- This is read-only. It does not pull, rebase, or merge.
- This is a convenience shortcut for seeing what the configured upstream has that the current local branch does not.

## In-Session Mode Switching

Status: Approved

All TUI screens should support `/` as a global mode switcher.

Expected behavior:

- Pressing `/` opens a popup command palette over the current screen.
- The palette lets the user jump to another approved workflow without exiting Diffy.
- The palette is keyboard-first and mouse-clickable.
- The current session state should update after selecting a new workflow.

Approved palette entries for now:

```text
Local changes
Compare/review branches
Ahead of upstream
Behind upstream
Recent commits
File compare
Stash
File history
Commit view
```

Example:

```text
run diffy
inspect local changes
press /
choose Compare/review branches
pick target branch
continue in compare view
```

Because `/` is global, per-list filtering should use another key or only happen inside focused input controls.

## Recent Commits

Status: Approved

```bash
diffy recent <count>
diffy recent <count> --file
diffy recent <count> --file <path>
diffy recent <count> --path
diffy recent <count> --path <path>
```

Shows changes across the last N commits on the current branch.

Examples:

```bash
diffy recent 1
diffy recent 3
diffy recent 10
diffy recent 3 --file
diffy recent 3 --file src/App.ts
diffy recent 3 --path
diffy recent 3 --path src/App.ts
```

Underlying Git commands:

```bash
git diff HEAD~<count>..HEAD
git log --oneline HEAD~<count>..HEAD
git diff HEAD~<count>..HEAD -- <path>
```

Expected behavior:

- Show the commits included in the range.
- Then show the combined diff for the range.
- `--file <path>` restricts the recent-commits diff to that file.
- `--file` without a path opens a file selector populated from files changed in the recent-commits range.
- `--path` is an alias for `--file` and works the same way.
- The recent TUI should have a shortcut to restrict to a file.
- When file restriction is active, the shortcut bar should show an action to remove the file restriction.

## File Compare

Status: Approved

```bash
diffy file
diffy file <path> <ref>
```

Compares the current working version of a file against a branch, commit, or ref.

This command is file-first. It overlaps with `diffy compare ... --file`, but it is kept because it starts from the question: "I know the file, what do I want to compare it against?"

Interactive behavior:

- `diffy file` opens a file selector first, then a branch selector.
- `diffy file --file <path>` skips the file selector and opens the branch selector.
- `diffy file <ref>` opens a file selector first, then compares the selected file against that ref.

Examples:

```bash
diffy file
diffy file src/App.ts main
diffy file src/App.ts HEAD~1
```

Underlying Git command:

```bash
git diff <ref> -- <path>
```

Compare a file across two refs:

```bash
diffy file <path> <from-ref> <to-ref>
```

Examples:

```bash
diffy file src/App.ts abc123 def456
diffy file src/App.ts main HEAD
```

Underlying Git command:

```bash
git diff <from-ref> <to-ref> -- <path>
```

## Stash Compare

Status: Approved

```bash
diffy stash
diffy stash stash@{2}
```

Opens the stash viewer and action screen.

Underlying Git command:

```bash
git stash list
git stash show -p
```

Specific stash:

```bash
diffy stash stash@{2}
```

Underlying Git command:

```bash
git stash show -p stash@{2}
```

Expected behavior:

- Left pane should show the stash list.
- Selecting a stash should show its changed files.
- Main pane should show the diff for the selected stash or selected file.
- The stash screen can mutate Git state. This is the intentional exception to Diffy's read-only default.

Expected layout:

```text
left top: stash list
left bottom: files in selected stash
main pane: diff for selected stash or selected file
bottom bar: shortcuts
```

Expected shortcuts:

```text
a apply    p pop    d drop/delete    r refresh    tab switch pane    q quit    / modes
```

Mutating actions must show a confirmation popup with the exact Git command before running.

Apply:

```bash
git stash apply stash@{n}
```

Pop:

```bash
git stash pop stash@{n}
```

Drop/delete:

```bash
git stash drop stash@{n}
```

Confirmation rules:

- `apply`, `pop`, and `drop` must never run from a single keypress alone.
- The confirmation popup should explain the effect in plain language.
- `pop` should say that it applies the stash and removes it if successful.
- `drop` should say that it permanently removes the stash.
- If local uncommitted changes exist, `apply` and `pop` should warn that conflicts are possible.

## File History

Status: Approved

```bash
diffy history
diffy history --file <path>
```

Shows commit history for a file, then shows how that file changed in the selected commit.

Default form:

```bash
diffy history
```

Expected behavior:

- Open a file selector first.
- After the user selects a file, open the file history view for that file.

File-first form:

```bash
diffy history --file path/to/file.ts
```

Expected behavior:

- Skip the file selector.
- Open the file history view for the given file directly.

Underlying Git command:

```bash
git log --oneline --follow -- <path>
```

File history layout:

```text
left pane: commits that touched the selected file
main pane: selected commit's diff for the selected file
bottom bar: shortcuts
```

Selecting a commit should show only that commit's change for the selected file in the main diff pane.

Underlying Git command:

```bash
git show <commit> -- <path>
```

or:

```bash
git diff <commit>^ <commit> -- <path>
```

Expected shortcuts:

```text
enter open commit/file diff    f changed files    c commit view    q quit    / modes
```

Changed-files shortcut:

- From a selected commit, pressing the changed-files shortcut opens a popup listing all files changed in that commit.
- Selecting a file from that popup moves to the history view for that selected file.
- The left commit list should stay anchored around the original commit when possible, so the user does not lose context.

All-changes shortcut:

- From a selected commit, pressing the commit-view shortcut opens the commit view for that commit.
- This should route to `diffy commit <commit>`.

## Commit View

Status: Approved

```bash
diffy commit <commit>
```

Shows all changes introduced by one commit compared to its previous commit.

Example:

```bash
diffy commit abc123
```

Underlying Git command:

```bash
git show <commit>
```

Expected behavior:

- Left pane shows files changed in the commit.
- Main pane shows the selected file diff or the full commit diff.
- The user can jump back to the originating history view when commit view was opened from file history.
- The command is read-only.

## Shared Options

Status: Approved

These should work across most commands where they make sense.

Approved:

```bash
--summary
--raw
--no-tui
--unified
--split
--path
--path <path>
--help
```

Meanings:

- `--summary`: print a compact summary and exit. It should include totals plus per-file additions and deletions.
- `--raw`: print the raw/full diff and exit instead of opening the TUI.
- `--no-tui`: alias for `--raw`.
- `--unified`: use unified diff view for this run.
- `--split`: use side-by-side diff view for this run.
- `--path`: alias for `--file`; restrict comparison to a path, or open a selector when no value is provided.
- `--help`: show global or command-specific help.

Summary output direction:

```text
3 files changed, +42 -9

src/App.ts          +20 -2
src/routes.ts       +12 -0
test/App.test.ts    +10 -7
```

Diff layout behavior:

- Default layout is split view.
- The default can be changed later through the config file.
- Passing `--unified` or `--split` overrides the configured default for that run.
- The TUI should also provide a shortcut to toggle between unified and split view.

## Open Naming Questions

- Should `diffy ahead` and `diffy behind` be grouped under `diffy upstream`?
- Should `diffy file <path> <ref>` put the path first or last?

## Future Ideas

These are intentionally parked outside the active approval list.

### Exact Ref Or Commit Diff

```bash
diffy commits <from-commit> <to-commit>
```

Possible meaning:

```text
compare snapshot A against snapshot B exactly
```

Possible underlying Git command:

```bash
git diff <from-commit> <to-commit>
```

Reason parked:

- It is more complex than the first command set.
- It overlaps with branch compare, but uses different two-dot/exact-endpoint semantics.
- Naming is not settled. Possible names: `commits`, `refs`, `range`, or something else.
